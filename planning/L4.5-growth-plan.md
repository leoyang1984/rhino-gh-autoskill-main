## 什么是 L4.5

Recipe 模式库阶段。把已验证的 GH 拓扑固化为可复用的 Recipe，让 AI 从"每次从零规划"变成"识别意图 → 匹配 Recipe → 注入参数"。同时支持多 Recipe 链式组合，形成完整建筑工作流。

## 每个 Recipe 的生产协议

```
Step 1  /gh-wire "<描述>"           → 生成 output/wiring.json
Step 2  GH 里运行 build_gh_file.py  → 打开 result.gh
Step 3  人工验证几何是否正确
Step 4  /gh-ok                      → 沉淀为 Recipe（自动写入 recipes/）
Step 5  （可选）链式组合测试         → compose → audit → 用户视觉确认 → admit
```

验证标准：几何形态符合设计意图，Slider 范围合理，无报错。
链式验证标准：Recipe A 的几何输出经桥接后真正成为 Recipe B 的输入，参数联动正确。

## Recipe v2 组合与准入机制

从 2026-04-13 起，链式组合验证走自动化流程：

```
识别链式意图
    → 读取 Recipe A/B 的公共 interface
    → compile_recipe.py compose 应用公共 composition_rules
    → Rhino MCP apply + solve + canvas data
    → compile_recipe.py audit 生成结构证据
    → 用户视觉确认并记录 approved
    → compile_recipe.py admit 只读检查
    → 用户要求保留后才更新 Recipe/knowledge
```

不得因图能求解就自动沉淀知识。新 Recipe 必须声明公共输入/输出，并同时通过静态验证、动态审计和用户视觉确认。

## 注意事项

- `mass-rotate` 已在 2026-04-12 验证通过，是第一批的起点
- 链式组合的 wiring.json 不作为独立 Recipe 入库；稳定规则写入 source Recipe 的 `composition_rules`
- 验证失败不是坏事——失败场景应记录在 `logs/` 中，供后续分析
- Recipe 只入库不淘汰，但可以在 recipe.json 中标注 `deprecated: true`
- 知识积累路径：`knowledge/composition-patterns.md`（桥接模式）+ `knowledge/geometry-type-guide.md`（类型兼容）
