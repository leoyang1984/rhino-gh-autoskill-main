# dev/ —— 开发管理区

> 本目录存放**项目本身如何改进**的工程文档：架构方案、技术债、优化计划、执行清单。
> 它是"元一层"（meta）目录：讨论的是这个代码库怎么开发，而不是用这个库去做什么。

## 定位边界（与其它目录的分工）

| 目录 | 性质 | 谁在什么时候读 |
|------|------|----------------|
| `knowledge/` | **运行时知识库**：GH 组合模式、类型兼容表 | `/gh-wire` / Skill 执行**组合任务时**按需读 |
| `docs/` | 静态技术规则：Rhino 8 Python 编码规范 R1-R6 | 生成 GH 内脚本**前**必读 |
| `recipes/` | 已验证 Recipe 库（参数契约 + 拓扑） | AI 匹配意图时读 |
| `planning/` | **产品战略**：路线图、成长计划、进度快照 | 新 session 开始时定位"在哪、下一步做什么" |
| `logs/` | 会话日志（做过什么） | 回溯历史时读 |
| `dev/` | **开发管理**：架构方案、优化计划、技术债、执行清单 | 决定"**项目本身怎么改**"时读 |

**一句话区分：**
- `planning/` 回答"产品往哪走、Recipe 队列做到哪"
- `dev/` 回答"代码库本身怎么改、按什么顺序改"
- `knowledge/` 回答"GH 拓扑怎么组合、类型怎么接"

## 约定

- 方案文档命名：`<主题>-<yyyy-mm-dd>.md`（如 `optimization-plan-2026-08-13.md`）
- 一个方案一个文件；执行中的事项用文件内"状态"小节标注（`提议 / 已采纳 / 进行中 / 已完成 / 已否决`），不另开散文件
- 技术债、待办清单集中放 `dev/backlog.md`（需要时创建）
- 决策记录（为何选 A 不选 B）写进方案文件末尾"决策记录"小节，方便未来 session 接手
